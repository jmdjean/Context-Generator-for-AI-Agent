# Exporters

Agent exporters translate the **Project Knowledge Model (PKM)** into agent-specific context files. They are generators — presentation layers — not analyzers.

---

## Responsibility

| Do | Do not |
|---|---|
| Consume `ProjectKnowledge` in memory | Scan the repository or read source files |
| Write derived outputs under the configured docs folder or agent-specific paths | Call OpenRouter or other AI APIs |
| Respect the generated-file marker policy | Overwrite user-managed files without the marker |
| Register through `exporter-registry.ts` | Bypass the pipeline from `cli.ts` or `core/` |

---

Renderers reuse `src/docs/markdown-renderers/render-helpers.ts` for formatting consistency with Markdown generators.

## Contract

`AgentExporter` defines:

- `id`, `name`, `description` — registry metadata
- `supports(target)` — whether this exporter handles an `ExportTarget`
- `export(knowledge, options)` — produce files and return an `ExportResult`

`ExportTarget` values: `generic`, `cursor`, `claude`, `codex`, `copilot`.

`DEFAULT_ENABLED_EXPORT_TARGETS` is `['generic']`.

---

## Registry

`exporter-registry.ts` lists registered exporters and exposes:

- `resolveExportersForTarget(target)` — exporters that support a target
- `findUnsupportedExportTargets(targets)` — targets with no exporter yet

Today:

| Exporter | Target | Output |
|---|---|---|
| `generic-agent-exporter.ts` | `generic` | `.ai-docs/agent-pack/AGENTS.generated.md` |
| `cursor-exporter.ts` | `cursor` | `.cursor/rules/ai-project-docs.mdc` |

Future exporters (Claude Code, Codex, Copilot) register here without changing the PKM contract.

---

## CLI targets

When `--export-agents` is passed:

| Flag | Behavior |
|---|---|
| (default) | Runs the `generic` exporter only |
| `--target generic` | Runs the generic agent pack exporter |
| `--target cursor` | Runs the Cursor rules exporter |
| `--target all` | Runs `generic` and `cursor` |
| `--target claude` / `codex` / `copilot` | Configuration error — no exporter registered yet |

`--target` requires `--export-agents`.

---

## Pipeline integration

Step **Export Agent Context** runs when `--export-agents` is passed. It:

1. Calls `runAgentExports()` from `agent-export-service.ts`
2. Runs exporters for the resolved targets from `RuntimeConfig.exportTargets`
3. Stores results and warnings in `analysis.agentExports`
4. Persists `.ai-docs/knowledge/agent-exports.json` during **Persist Project Knowledge**

When `--export-agents` is omitted, the step is skipped.

When `--export-agents` is omitted, the export step is skipped. The previous `agent-exports.json` split file and any generated agent pack on disk are **preserved** — they are not deleted on persist.

## Cursor exporter

The Cursor exporter writes `.cursor/rules/ai-project-docs.mdc` at the repository root. The rule uses `alwaysApply: true` so Cursor loads project context on every session.

Content is derived from the PKM only:

- Project summary
- Mandatory reading order
- Architecture boundaries (folder classifications and architectural conventions)
- Module map
- Convention summary
- Navigation map by task type
- Dependency graph summary
- Safety rules
- Instruction that `.ai-docs/knowledge/project-knowledge.json` is the source of truth

Cursor rules are a **presentation layer**. They format PKM facts for the Cursor runtime; they do not discover new facts or replace the PKM.

---

## Generated-file policy

Every tool-managed export starts with:

```md
<!-- Generated by AI Project Docs. Safe to update. -->
```

`export-file-writer.ts` mirrors the Markdown documentation writer: existing files without that marker are skipped with a warning.

---

## PKM is the source of truth

Exported files are **derived outputs**. Facts come from deterministic analyzers assembled into the PKM. Exporters format those facts for a specific agent runtime; they do not discover new facts.

Agent-specific files (generic packs, Cursor rules, future Claude/Codex/Copilot outputs) must never become the source of truth. When outputs disagree, trust `.ai-docs/knowledge/project-knowledge.json`.

Load `.ai-docs/knowledge/project-knowledge.json` for the canonical snapshot. Regenerate exports after PKM sections change:

```bash
ai-project-docs ./my-project --export-agents --target cursor
ai-project-docs ./my-project --export-agents --target all
```

Future exporters should follow the same contract: consume `ProjectKnowledge`, write formatted files, preserve the generated marker, never analyze the repository.
