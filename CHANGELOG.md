# Changelog

All notable changes to `ai-project-docs` are documented here.

---

## [1.0.0] — 2026-07-10

First stable MVP release of the Context Engineering CLI.

### Architecture

- **Project Knowledge Model (PKM)** — single source of truth assembled at `Build Project Knowledge` and consumed by all generators; persisted as `project-knowledge.json` and split section files under `.ai-docs/knowledge/`
- **18-step declarative pipeline** — pure data in `src/domain/pipeline.ts`; execution in `src/core/pipeline-orchestrator.ts`; handlers dispatched by name so steps can be removed or replaced without renumbering
- **Plugin architecture** — deterministic analysis runs through `PluginManager`; built-in analyzer plugins wrap existing enrich functions and return `PluginContributions` merged by `plugin-merger.ts`; technology plugins isolate framework-specific detection from the core
- **Template engine** — lightweight PKM-to-Markdown renderer in `src/templates/`; renderers are presentation-only with no filesystem access or AI calls
- **Provider-based AI architecture** — `AIProvider` contract in `src/ai/providers/`; OpenRouter is the default and only built-in provider; providers receive a compact PKM summary prompt, never source files

### Features

#### Repository scanning and detection

- Walk directory tree up to `maxDepth=12` / `maxFiles=10000` with `.gitignore`-style ignore rules
- Detect programming languages, frameworks, package managers, and tooling with confidence levels
- Detect TypeScript, JavaScript, Angular, React, NestJS, Node.js stacks

#### Deterministic analyzer plugins (via PluginManager)

- `builtin.folder-analyzer` — classifies and describes every scanned folder
- `builtin.module-analyzer` — discovers application, library, and feature modules from structural heuristics
- `builtin.dependency-analyzer` — detects import relationships between modules
- `builtin.convention-analyzer` — extracts project conventions from PKM data and config files
- `builtin.navigation-analyzer` — builds a task-to-document navigation map for AI agents

#### Documentation generation

- 8 registered PKM-powered Markdown templates: `architecture.md`, `folder-structure.md`, `dependency-map.md`, `conventions.md`, `agent-navigation.md`, `ai-context.md`, `implementation-guide.md`, `ai-readiness.md`
- Generic deterministic fallback for any document without a registered template
- Generated-file protection marker (`<!-- Generated by AI Project Docs. Safe to update. -->`) — user-managed files without the marker are always preserved

#### AI Readiness Score

- Deterministic 0–100 Context Engineering assessment; six weighted categories (repository structure, architecture knowledge, documentation coverage, agent navigation, project conventions, context maintainability)
- Scoring rules versioned at `1.0.0`; identical PKM input always yields the identical score
- Results persisted to `ai-readiness.json` and rendered as `ai-readiness.md`
- Validated immediately after writing; write failures and structural issues surface as validation errors

#### Incremental change detection and selective regeneration

- Compares current PKM to the previously persisted snapshot; records `change-summary.json`
- Derives `document-impact.json` for selective Markdown regeneration — only impacted tool-managed files are rewritten on re-runs
- User-created files without the generated marker are always preserved

#### Optional AI enrichment

- Activated by `--ai` flag; requires an OpenRouter API key (`--openrouter-key` or `OPENROUTER_API_KEY`)
- Enriches `architecture.md`, `ai-context.md`, `implementation-guide.md`, and `agent-navigation.md` with non-authoritative AI insights
- AI failures never fail a deterministic run; invalid responses warn and continue

#### Agent exporters

- `generic` — outputs `AGENTS.generated.md` under `.ai-docs/agent-pack/`
- `cursor` — writes an always-on Cursor rule to `.cursor/rules/ai-project-docs.mdc`
- Both activated by `--export-agents [--target generic|cursor|all]`

#### CLI

- Full argument parsing, help text, and documented exit codes
- Exit `0` success, `1` config error, `2` validation failure, `3` runtime error
- Optional AI analysis never downgrades a deterministic `0` exit to an error

#### Security and safety

- All writes use `resolvePathWithinRoot()` — no escaping the target repository root
- Symlinks skipped during scan; `.git`, `node_modules`, and configured docs output excluded
- API keys never printed; prompts never include source files or secrets

### Release gates

All of the following passed before tagging 1.0.0:

- `npm run clean && npm run build` — zero TypeScript errors
- `npm test` — 364 unit and integration tests passing
- `npm run smoke` — end-to-end CLI smoke test passing
- `npm pack --dry-run` — tarball contains only whitelisted files

### Known limitations

- Full repository scan on every run; only Markdown regeneration is selective
- AI analysis is opt-in (`--ai`); only OpenRouter is supported as a provider
- Agent exporters: only `generic` and `cursor` implemented; `claude`, `codex`, and `copilot` are reserved
- Technology plugins (Angular, React, NestJS, Node.js) implement detection; framework-specific analysis is a placeholder
- Large repositories may hit scanner limits (`maxDepth=12`, `maxFiles=10000`); `truncated` is flagged in the PKM
- No file watching, Git hooks, or remote dashboard

### Post-1.0 roadmap

- Additional AI providers (OpenAI, Anthropic, Gemini, Azure OpenAI, Ollama, local models)
- Agent exporters for Claude Code, Codex, and Copilot
- Framework-specific analysis in technology plugins
- Readiness history tracking and trend badges
- VS Code extension and desktop UI
- Custom user templates
- File watcher and Git hook integration
